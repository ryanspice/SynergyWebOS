# Native UI internationalization

Status: **first increment**. The native management UI ships in English by
default; Quebec French (`fr-CA`) is the first test locale. This is UI text only.

## What changed

| Path | Role |
|---|---|
| `include/synergy/i18n.hpp`, `src/i18n.cpp` | Locale enum, `tr()` catalog, `{placeholder}` interpolation, tag mapping. |
| `src/ui.cpp` | All panel labels, notices and buttons use `T(key, args)`; top-bar **Language** button toggles en ⇄ fr-CA and saves. |
| `include/synergy/config.hpp`, `src/config.cpp` | `Config::locale` is part of the typed, persisted config (daemon `saved_config`). |
| `CMakeLists.txt` | `src/i18n.cpp` added to `synergy_core`. |
| `tests/core_tests.cpp`, `tests/ui_regressions.cpp` | Catalog/config checks and the toggle/persistence regression. |

English remains the default when the field is absent, so existing saved configs
and the 0.4.x app/daemon contract are unchanged apart from one optional field.

## How it works

- `locale_from_string()` maps `en`/`en-*` and `fr`/`fr-*` to the two supported
  locales. Config validation accepts only the canonical stored values `en` and
  `fr-CA`.
- On first status result the UI loads `saved_config` into `Config` and sets its
  locale. A locale chosen before that result arrives is preserved
  (`locale_dirty_`), so the first frame cannot revert it.
- The **Language** button cycles the locale, updates the drawn strings
  immediately and posts a `configure` request so the daemon persists it. The
  setting survives UI and daemon restarts.
- `tr()` falls back to the key name for unknown keys; `catalog_valid()` asserts
  every key has unique, non-empty English and French entries.

## Scope / follow-up

Translated: the four management panels (Connection, Input, Handoff,
Diagnostics), edit overlay, notices, status label and footer.

Deliberately not translated:

- Protocol values and daemon-supplied errors/log lines (`client.state` values
  are mapped for display only), so log parsing and control contracts stay
  stable.
- The on-screen keyboard character set and LAN/IP/screen-name input values.
- The `app/` web shell and `desktop/input-bridge/` companion; this change is
  native TV UI only.

Adding a locale means adding an `Entry` column/set in `src/i18n.cpp`, extending
`Locale` and its two mapping functions, and updating the toggle cycle in
`src/ui.cpp`. The catalog validity test will catch a partial translation.

## Verification

```powershell
pwsh -NoProfile -File native/scripts/Build-Desktop.ps1
```

On this machine the WSL wrapper needs an explicit distribution and a private
fixture root because the Windows path resolves as `/mnt/b`:

```powershell
wsl.exe -d WebOSBuild -- cmake -S /mnt/b/Dev/SynergyWebOS/native -B /mnt/b/Dev/SynergyWebOS/native/build/i18n -G Ninja -DCMAKE_BUILD_TYPE=Release -DSYNERGY_STRICT=ON
wsl.exe -d WebOSBuild -- cmake --build /mnt/b/Dev/SynergyWebOS/native/build/i18n --parallel 4
wsl.exe -d WebOSBuild -- mkdir -p /tmp/syfixall
wsl.exe -d WebOSBuild -- chmod 700 /tmp/syfixall
wsl.exe -d WebOSBuild -- env SYNERGY_TEST_POSIX_ROOT=/tmp/syfixall TMPDIR=/tmp/syfixall ctest --test-dir /mnt/b/Dev/SynergyWebOS/native/build/i18n --output-on-failure
```

A rendered headless check used a real daemon with `locale=fr-CA`, DejaVu Sans
and `synergy-tv --frames 2 --screenshot` under `xvfb-run`; the accented Quebec
French text rendered correctly at 1920×1080 and the persisted locale was read
back by the UI. Those captures are local evidence under `.ai/evidence/` and are
not committed.
